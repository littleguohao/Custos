## 主题

R36 Phase 3 想回答「V0 的 30 条腿换一套配比，能不能比 live 默认权重更好」，但 64 格里 61 格是「单腿独跑 / 关一条腿」，
倍率 3 零覆盖、无任何同时调两条腿的格——**问题没被检验过**。本单元换一个能真正覆盖配比空间、又付得起零假设的设计重问一次。

## 目标

在挖掘 A∪B 上搜索 V0 打分的**家族级**倍率配比，判断是否存在一组配比在两段挖掘窗都稳定胜过 live 默认权重、且胜过
「同样搜索预算下打乱打分—收益对应关系」的零假设；过线则冻结入判定段批次。非目标（写死）：不动 live 权重（回流走立项 +
影子观察）；不加新腿（腿集合 = V0 现行 30 条）；不改出场（j_low gate + pct5_trail08 + top20 + 25bps，同 R36）。

## 结论

**📋 预注册定稿，尚无读数。**

- **机械判决**：待读数（`criteria_kit.verdict_four_state` 四态）。
- **实质读数**：暂无。
- **不能读成什么**：①家族级配比胜出 ≠ 某条腿有用（家族内等比缩放）；②只在本出场口径下成立；③过线也只说明「配比有增量」，
  打分系统要不要留（R35 #87）另判；④绝对读数不代表实盘（R11 / R14）。

### 实验单元（写死，D1）

- **入场 / 出场 / 组合**：同 R36（V0 + j_low gate + 0AMV 做多、pct5_trail08、top20、V0 组合口径、25bps），宇宙 = 全量 as-of。
- **打分**：score = clamp₀¹⁰⁰(Σ_f m_f · S_f)，S_f = 该候选在家族 f 的 V0 子分（按默认分值求和）；m ∈ {0,1,2}⁶。
  **工程要点**：S_f 每候选只算一次（6 维向量），729 格只是矩阵乘 + 组合模拟——collect 一次、逐格重打分（同 R36 v0-lattice）。
- **基准格**：m = (1,…,1) = live 默认权重（不经挑选）；rdd 相对门参照 = 基准格。
- **平分**：家族倍率格仍是整数分，top-N 截断平分频繁 ⇒ 每格按平分种子 0~19 读、取中位数（同 R36 v2 `--frozen-read`）。
- **窗口**（v2）：选格只用挖掘 A ∪ B；两步走同 R39/R40——①预演（A 选格、B 验证，不触判定段）②入批（冻结格读判定段）。

### 判据（跑数前写死，D1）

- **C1 样本**：两段挖掘窗各自基准格 n_taken ≥ 100。
- **C2 存在更优配比**：g* = A∪B 合并 Δmargin（vs 基准格）最高且过 rdd 相对门的格；要求 g* 在 A、B **各自** Δmargin > 0 且过门。
- **C3 稳健**：g* 的 12 个邻格（每家族 ±1 档，越界不计）中 ≥ 2/3 在 A、B 两窗 Δmargin 均 > 0。
- **C4 选择效应**：零假设臂 N = 100（过门臂数）——**簇级置换**打乱「打分 ↔ 收益」对应：以 `kit.cluster_ids` 的簇（同票
  相邻信号）为单位，把簇内各候选的家族子分向量整体随机指派给同段内同长度（长度分层）的另一簇，再跑**同一套 729 格**取
  max Δmargin；g* 的合并 Δmargin > 置换判定线（`kit.q95`）⇒ confirmed_pass。逐候选置换会拆散成簇的打分持续性、低估零假设
  方差（R39/R42/R40 同病），故写死簇级。
- **结局**：C1~C4 全过 = candidate ⇒ g* 冻结入判定段批次（判定段池 = 同次运行每条置换臂冻结格的判定段读数，判定线
  `judgment_line`，m 来自名册）。副读数（不作判据）：64 个家族开/关子格的 Δmargin 表（#87 选项 B 的证据）。

### 功效（#92 后回填）

- 输入：#92 给出两段挖掘窗 j_low 候选数、top20 选中数、基准胜率；相邻格配对相关 ρ_pair、日簇 deff。
- 跑数前规则（写死）：Δmargin 的 MDE（k=2.8）> 3pp ⇒ 档位收缩为 {0,1}（即 D3，64 格）再估，仍 > 3pp ⇒ untested 不跑。
- **回填（2026-10-17，#92）**：j_low 候选密度 A≈69.1/日（4246 交易日）、B≈241.3/日
  （1244 交易日）；top20 选中上限 A≈84,920 / B≈24,880（A 早期信号稀，实际低于上限）；
  基准胜率 0.44~0.45；相邻格同候选集换家族配比，ρ_pair 取 0.75；按保守 n=24,880：
  `power_mde --wr 0.44 --n 24880 --rho 0.75`：MDE ≈ **0.62pp**（deff=1）/ ≈ 1.4pp
  （deff=5）≪ 3pp ⇒ **维持 729 格（{0,1,2}），不收缩、不触 untested**。

### 写死的风险注记

1. **先验弱**：R30/R34/R36/R42 在打分侧全部证伪，判负是默认预期；
2. **clamp 非线性**：倍率 2 可能把大量候选顶到 100 分，造成新一轮平分——报告每格「满分占比」，> 30% 的格不参与选 g*；
3. **家族划分是主观的**：只在跑数前定一次，读数后不得改划分重跑（改划分 = 新单元）。

### 定稿修订（v0.404，跑数前；实现时发现，判据实质不放松）

1. **平分口径**：草案「每格按平分种子 0~19 读、取中位数」在 729 格 × (1 + 100 臂) 下是 ~300 万次组合模拟，付不起。
   改为：**选格与零假设臂都用平分种子 0**（两边同口径，选择效应对称）；g* 另按种子 0~19 读 Δ 中位数作**稳健闸**——
   任一挖掘段中位数 ≤0 ⇒ C2 不过（比原文更严：原文只用中位数，现要求种子 0 与中位数同时 >0）。
2. **满分占比**：风险注记 2 的「满分占比 >30% 的格不参与选 g*」落为代码硬规则（`FULL_SCORE_MAX`）。
3. **C2 合并口径**：A∪B 合并 Δmargin = 两段 top-N 选中子集并集的 margin − 基准格同口径；g* 还须两段**各自**过 rdd 相对门。
4. **矩阵化**：`technical_score` 各段对权重线性（repair 的 min(次数×each, cap) 对非负倍率同比缩放），
   故 score(m) = clamp₀¹⁰⁰(Σ m_f S_f)；`tests/test_family_lattice.py` 在 1500+ 个（候选, 格）上与 `technical_score` 逐位一致。
5. **挖掘 A 起点**：`--mining-a-start`（= SEG_A_START，#91 回填前缺省 2000-01-01）；两段各自段末 90 天隔离带。

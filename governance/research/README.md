## 研究纪律

### 写入规范

- 一个单元 = 一个**研究问题**。新结论追加到该单元的「证据与过程」，并**同步更新头部
  「状态」与「结论」段**——判毕后头部/结论段不得再写「待跑数/待发令」（测试强制）。
- 结论被推翻时**不删除旧结论**，标 🔄 并写清被什么推翻（见 R10）。
- 每条结论带**证据等级**；拿不出等级的，说明它还是猜测。
- 编号只增不复用（R38 已被 live-only 出场回测化预留）。
- 结论段用三栏模板（v0.321 起新单元强制）：**机械判决 / 实质读数 / 不能读成什么**。
- 判据**跑数前写死**；跑数前的修订要在文档里留「修订」注记——产物记录预注册文档的
  blob hash，`test_prereg_revision_notes.py` 机械核对。
- 新单元的预注册必带「**功效**」节：用 `power_mde` 估 MDE，MDE 大于合理效应就在跑数前
  合并桶或改问法。配对比较用 `rho_pair`；组间（不配对）比较 `rho_pair=0`；同日成簇用
  `deff`。两者方向相反，不要混用。
- **三维度搭配**（owner 2026-08-21）：策略类研究以 **因子 × 止损 × 止盈** 为实验单元，
  不单跑「只换因子」或「只换出场」下结论（R10：`cost_zone` 在 A 组 ❌、在择时上下文最优）。
- **默认研究基底**（v0.93）：0AMV 做多区间 + J<13 钉死、不作扫描变量；扫描的是叠加
  其上的 gate/scorer 与出场参数（`--no-amv-pin` 仅对照用）。

append-only、生产机写入提交）：

1. **冻结**：打算跑数的那条命令加 `--print-config-hash` → 打印 `<tool>:<hash>`（不碰数据）；
2. **开批**：`uv run python -m custos.research judgment_batch open --batch-id b1 \
   --candidate r36_adx_gt_60:<hash>:R36:备注 [--candidate ...]`（批次号只增不复用，空名册拒）；
3. **跑数**：原命令加 `--batch-id b1 --candidate-id <id>`——候选不在批/哈希不匹配/已读/批已关

   需重读由 owner 手动开新批），跑完补 read；合成运行（注入件）与判定窗不接触

   漂移，count 只影响起点可达性，check_reach 兜底）；
4. **关批**：末位候选读完自动关；手动 `judgment_batch close --batch-id b1`；
   `status [--batch-id]` 查批状态/已读/未读清单。

### 三个根因

1. **qlib `2021_2026` bundle 是加法调整**（`raw − qlib` 分段常数，段差 = 每股现金分红）
   ⇒ 百分比收益放大 13~21%。已弃用，见 [`../data/QLIB_LOCAL_DATA.md`](../data/QLIB_LOCAL_DATA.md)。
2. **2021 年后退市的票一只都没有** ⇒ 近期窗口**无法去幸存者偏差**。
   老 bundle 的 214 只退市票只覆盖 1999-2020。
3. **基准边际随样本量崩塌**（R11）⇒ 相对判定的基准盘几乎为零。

### 一条方法论教训

R2 那次翻转**同时换了宇宙和数据源**。当时把翻转全部归因于幸存者偏差，
而现在已知另一个变量（加法调整）也会显著改变收益 ⇒ **归因不成立**。
⇒ **对照实验一次只换一个变量**；换两个就只能得到「有变化」，得不到「因为什么」。
